## Context

In a few months, we moved from an editor assistant to agents that can explore a repository, edit files, run tests, and prepare a PR. We use **Claude Code** and **Codex**, among others, and we are experimenting with **Herd** to operate several native agents from one interface.

“Which one is best?” proved unhelpful. The right tool depends on the shape of the work: an interactive investigation, a well-specified task that can be delegated, or several independent units that need coordination.

## The problem

Every agent promises throughput. The hidden cost sits in context preparation, supervision, conflict resolution, and review. Running ten agents against an uncertain design does not multiply capacity by ten; it produces ten interpretations to reconcile.

Tool choice also changes operational boundaries: where code runs, which secrets are available, how actions are approved, where logs remain, and who can stop a task.

## Bad ideas

- Choose from a benchmark or isolated demo.
- Assign one tool to every team workflow.
- Confuse parallel work with independent work.
- Supervise more sessions than the team can review seriously.
- Give an exploration agent and a delivery agent identical permissions.
- Measure gains in lines of code instead of time to a reliable, reviewed change.

Agent output is not throughput until it is integrable.

## What did not work

Constantly switching tools lost the context we expected to gain. Every transfer required another summary and reintroduced assumptions.

Parallelising coupled tasks created file collisions and incompatible decisions. An orchestrator exposes these collisions; it does not remove them.

Long tasks without checkpoints also produced impressive but difficult-to-review diffs. The agent optimised its completion condition, not our ability to understand the change.

## Alternatives

We distinguish three modes rather than three brands:

| Mode | Good fit | Primary control |
| --- | --- | --- |
| Interactive pairing | Ambiguous problem, exploration, debugging | Frequent human direction |
| Bounded delegation | Clear issue, testable criteria, isolated diff | Sandbox, budget, completion evidence |
| Orchestration | Genuinely independent tasks | Worktree isolation and explicit integration |

Claude Code and Codex can cover several modes depending on their environment. Herd adds multi-agent supervision; its value appears when decomposition is already sound and an operator must track several flows, not while the problem is still being discovered.

## The solution

We select the mode from risk and uncertainty:

1. **Understand before parallelising.** One person and one agent explore until boundaries are clear.
2. **Define a task contract.** Scope, authorised files or systems, completion criteria, expected tests, and stop condition.
3. **Delegate the smallest unit that produces reviewable value.**
4. **Parallelise only independent units.** Each agent works in an isolated environment.
5. **Integrate under human accountability.** Review invariants, not only the diff and tests.

Our decision framework considers five costs: time to first evidence, context handling quality, action controllability, review effort, and supervision load. The best tool minimises total workflow cost; it is not necessarily the fastest writer.

## Limits

This framework reflects our organisation, repositories, and security constraints. Products evolve quickly; a model or interface advantage can disappear within weeks. We must reassess real workflows rather than defend an old ranking.

Multi-agent orchestration adds a distributed system to engineering work: queues, partial states, conflicts, and recovery. For short or tightly coupled tasks, it often increases total time. The right place for a tool can be outside the workflow.
