## Three dashboards walk into a meeting

Three dashboards answer the same question with three different numbers. The queries run and the charts look fine, but the meeting stops: what, exactly, did we count?

Self-service keeps every business question from becoming a ticket for the data team. People need room to investigate without waiting.

At RockFi, that also means protecting confidential data and keeping definitions for assets, flows, and clients consistent. A fast number is little help if nobody can trace its calculation.

## SQL can be right while the number is wrong

Two correct SQL queries may disagree on grain, effective date, or cancellation treatment. The difference can remain hidden until someone makes a decision.

We need **verifiable semantics** to understand, reproduce, and challenge the number.

## The warehouse is not a vending machine

Opening every table pushes the difficult domain decisions onto whoever writes the query.

Certifying a dashboard is not enough if its metrics have no contract. Copying domain logic into each query creates variants; an AI answer without provenance hides the same problem.

At the other extreme, treating every rough exploration like regulatory reporting discourages investigation. Exploring and publishing need different permissions.

## Where the “source of truth” starts multiplying

A dictionary that describes columns but omits grain or exclusions ages quickly. A “source of truth” dashboard with a definition locked in private SQL is just as fragile: when another dashboard copies the calculation, the versions diverge.

An agent querying raw tables speeds up the mistake. It may choose a plausible join without knowing which domain invariant to preserve.

## Give every shared metric a passport

A shared metric needs a contract before it feeds dashboards or decisions:

| Element | Question to settle |
| --- | --- |
| Meaning | Which decision does this number support? |
| Grain | What does one row represent? |
| Population | Which entities are included or excluded? |
| Time | Event date, effective date, or snapshot? |
| Owner | Who resolves ambiguity? |
| Evidence | Which tests and reconciliations protect the calculation? |
| Freshness | When is the result no longer usable? |

When results disagree, there is a definition to compare, an owner to ask, and checks to rerun.

## Self-service needs three lanes

Not every question should pass through the same controls. We keep three levels distinct:

1. **Exploration** allows bounded access, temporary output, and visible assumptions.
2. **Certified metrics** add a versioned definition, owner, tests, and freshness policy.
3. **Decisions or publications** display provenance, enforce access controls, and receive review proportional to their impact.

A semantic layer holds shared formulae, a catalogue shows owners and freshness, and governed marts isolate sensitive data. None replaces the domain contract.

## Make the assistant show its working

AI assistants start with certified models, show their sources, and flag when they leave that boundary. Before publication, someone must be able to verify the result.

## A badge is not evidence

Contracts and freshness need maintenance. A one-off analysis can remain exploratory. A semantic layer cannot fix a wrong source: a “certified” badge is only as good as the evidence and ownership behind it.
