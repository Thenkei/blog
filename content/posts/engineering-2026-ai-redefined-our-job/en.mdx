Our work has changed considerably over the past few months. At **RockFi**, we write less code by hand and spend more time framing requests and checking the changes agents propose.

## December: leaving Cursor for Claude Code

<ArticleDiagram visualId="engineering-2026-ai-redefined-our-job" />

In late 2025, around December, the tech team (10 to 12 people at the time) moved from Cursor to **Claude Code**. We wanted an agent that could work in the terminal and repository, with the project's constraints, rather than complete our lines of code.

Nobody had to mandate the migration: people tried the tool on their tasks and switched on their own.

I can delegate part of an implementation with the repository's files and conventions. I then need to check how the agent interpreted them, especially when a change affects several services.

## Internal tools for repetitive tasks

We built tools around Claude Code for tasks that kept recurring:

- **Workshops and brainstorming**: gather relevant context and structure the discussion.
- **DiveIn preparation**: organise decisions and open questions in our design template.
- **PR preparation**: create the branch, retrieve context, draft the description, and link the documents.

These tools save us some repetitive work. We still have to check that the document captures the decision correctly and that the PR addresses the need.

## Why I keep Codex and Claude Code

Alongside the team's shared stack, I use **Codex** and **Claude Code** in parallel.

I mostly use Codex for focused changes with short feedback loops. Claude Code is what I tend to open to discuss an architecture decision or debug a distributed issue that requires more context. That is how I divide my work at this point, rather than a limit on what either tool can do.

With that pair, I work across **4 to 5 projects a day**. An observability regression in one repository, a database migration to review in another, and my main project moving forward in between.

I have not become a multitasker; my brain is still single-threaded. The tool keeps track of each repository, which helps me resume a topic I left two hours earlier. The context switching remains; I have less context to rebuild each time.

## Time spent on review

Generating a first version takes less time. Review still takes time: checking business behaviour, understanding a migration, examining database access. We already did this work before AI. Keeping up becomes harder when diffs arrive faster.

Code review skills in Claude Code and Codex provide a first pass. They can flag a problem or suggest an additional check. We then need to examine those comments and the diff against the system's constraints.

## Supplying the context

The agent needs to know which conventions apply, which contracts to preserve, and which parts of the system are involved. In an older repository, it may find several patterns and follow one we no longer use.

Choosing the files and decisions to provide is therefore part of the work. The result can be consistent with the supplied context and incompatible with a constraint we left out.

## Another dependency on APIs

An Anthropic or OpenAI outage would slow down tasks we have grown used to delegating. It is another dependency in our workflow. We need to be able to resume those tasks without the agent, even if that takes longer.
